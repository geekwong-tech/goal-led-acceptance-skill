# 围绕目标逐步验收

[English](SKILL.md) | 简体中文。中文场景阅读本完整版本即可，无需将两个版本重复加载到上下文。

帮助用户判断交付物是否支持预期目标。验收由用户作出，助手的分析为这一判断提供支持。

## 先建立判断逻辑

向用户索要资料之前，先读取项目权威入口、当前成果、历史决策及已有证据。复用已有授权和已验收决策。简要说明成功定义、范围、必要条件和因果假设。假设应明确标为假设。如果用户的理解发生变化，先修正判断逻辑，再考虑是否沿用原结构。

建立映射：目标 → 必要条件 → 实际交付物的组成部分 → 内容或行为 → 支持证据 → 下一步。网站的组成部分可以是页面与模块；手册可以是说明与任务。以用户能作出实际判断为标准选择粒度，不强加页面数量、领域词汇、框架或工具。

只先给简短验收路径，再开始一个验收单元。除非新证据影响原结论，否则保留此前已验收的单元。

## 一次带领一个单元，然后等待

每个面向用户的验收单元包含：

1. **目标与逻辑：** 本环节要完成什么，为什么有助于核心目标。
2. **需要的答案与依据：** 用户或受众需要知道什么、做到什么，什么能够支持这些答案或行为。
3. **实际匹配：** 指向真实材料或可运行位置，逐项匹配相关要求与实际内容、行为和证据。区分已查看材料与当前无法取得的材料，不虚构检查过程。
4. **判断：** 通过 / 部分通过 / 不通过 / 待验证，并说明具体缺口与下一步。这是助手提出的判断，不等于用户已经验收。
5. **用户决定：** 明确本轮只需确认的一件具体事情，并给出可操作的查看路径。停止推进，等待用户回复后再进入下一单元。

需要具体输出形式时，阅读[虚构示例](references/example.zh-CN.md)。详细程度应服务于当前决定，不要一次发出整套验收报告。

如果用户要求跳环、加快或批量验收，应调整节奏，并记录哪些检查尚未审阅。沉默不等于验收通过。

## 让结论不超出证据

有助于理解时，标明验证责任：

| 类型 | 能够确认什么 |
| --- | --- |
| MACHINE（工具检查） | 工具检查到的结构、链接、计算或可观察行为 |
| HUMAN（人工判断） | 用户理解、优先级、判断与明确验收 |
| EXPERIMENT（实验验证） | 在明确人群、方法和指标下测试得到的实际效果 |

分别核验事实真伪、来源能够支持的主张范围及公开权限。未知不等于错误。结构完整不等于答案正确；答案正确、测试通过也不能证明业务效果。

说明当前验收阶段：概念、设计、演示、上线或实际效果。证据不足可能使某项主张或后续阶段暂缓，同时仍允许当前作出有边界的设计决定。不要把每一个未知都当作停工条件。记录可能导致后续决定失效的依赖。

简短记录已验收单元、暂缓检查、决策及下一单元。没有相应明确授权与证据，不得关闭任务、发布或宣布生产就绪。调用本 skill 本身不授予这些权限。
